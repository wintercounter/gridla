# Design context

## Product

Gridla is a pixel-based grid and nested-layout engine. Its public surfaces are
the README, the documentation site, a demo gallery, and a React layout studio.

## Audience

Frontend engineers evaluating or integrating a layout engine for dashboards,
page builders, and editor-style tools. They read API docs, drag things in
demos, and inspect coordinates. Expert users; impatient with fluff.

## Jobs to be done

- Judge in one minute whether the engine's behavior (push, swap, snap, project)
  is what they need.
- Copy a working snippet for vanilla JS or React.
- Inspect exact layout data while interacting.
- Build a non-trivial nested layout in the studio without documentation.

## Personality

Drafting table. Precise, warm, unhurried. Think engineering drawings on warm
paper, ink lines, one accent color used only where something is happening.
Confident but never loud. Data is typeset with care. Nothing glows.

## Aesthetic direction

- Light theme: warm paper ground, ink text. Dark theme: deep blue-black ink
  ground, paper text. Both tinted toward the brand hue; no pure black/white.
- One accent: vermilion, reserved for the active element, previews, snap
  lines, and primary calls to action. A secondary cool blue for selection.
- Typography: Familjen Grotesk (display), Instrument Sans (body),
  JetBrains Mono only for coordinates, code, and dense numeric data.
- The grid is the motif: fine rules, cell marks, and snap guides appear as
  decoration only where they carry meaning.
- Motion: short (120–220ms), ease-out-quint, transform/opacity only; honors
  reduced motion.
- Layout: asymmetric, left-aligned, generous separation between sections,
  tight grouping within controls. No card-in-card nesting.

## Constraints

- No runtime UI framework or CSS-in-JS in the public site or demos; plain CSS
  with custom properties and container queries.
- Every demo must work with keyboard, at 360px width, and in both themes.
- Docs are built with Rspress and served under a repository sub-path.
